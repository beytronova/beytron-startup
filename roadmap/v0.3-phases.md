# v0.3 Phased Roadmap

## Phase 1: Routing & Registry Foundation

Status: Completed

Purpose: Make Codex route requests through central maps before selecting workflows, roles, skills, tools, and artifacts.

Delivered:

- `config/role-skill-map.yaml`
- `config/workflow-map.yaml`
- `config/tool-access.yaml`
- `AGENTS.md` routing update
- `README.md` routing update
- `.codex-plugin/plugin.json` version `0.3.0`

## Phase 2: Missing Core Skills

Status: Completed

Purpose: Add missing primary skills for architecture, analytics, and security review.

Delivered:

- `skills/architecture/SKILL.md`
- `skills/data-analytics/SKILL.md`
- `skills/security-review/SKILL.md`
- `config/role-skill-map.yaml` updated to remove missing skill placeholders
- `config/workflow-map.yaml` updated to route architecture, analytics, and security review skills

Outcome:

- Every role now has a concrete primary skill.
- PRD-to-architecture routing no longer references missing architecture skill.
- Release-to-growth routing no longer references missing analytics skill.
- Security review can be triggered consistently from architecture, development, QA, and release.

## Phase 3: Integration Contracts

Status: Completed

Purpose: Define how external tools are used safely and consistently.

Delivered:

- `integrations/github.md`
- `integrations/jira.md`
- `integrations/web-search.md`
- `integrations/figma.md`
- `integrations/release.md`
- `config/tool-access.yaml` updated to link each tool to its integration contract

Outcome:

- Tool usage is predictable.
- Side effects require explicit approval and workflow permission.
- Outputs from tools are captured in artifacts and handoffs.
- GitHub, Jira, web search, Figma, and release system usage now have failure handling rules.

## Phase 7: Versioning & Release Discipline

Status: Completed

Purpose: Track plugin changes and release expectations.

Delivered:

- `CHANGELOG.md`
- `RELEASE_POLICY.md`
- `CONTRIBUTING.md`
- `README.md` updated to document the release discipline layer.
- `AGENTS.md` updated with plugin-change and release approval rules.

Outcome:

- Plugin evolution is auditable through changelog entries.
- Future role, skill, workflow, integration, checklist, template, example, and governance changes have a clear contribution process.
- Release publishing is gated by `Approval Status = APPROVED_FOR_RELEASE`.
- Version impact is now classified as major, minor, or patch.
