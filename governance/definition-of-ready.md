# Definition of Ready

A ticket is ready for development only when all required product, technical, approval, and test inputs are available.

## Required Inputs
- Linked PRD or product scope
- Linked architecture or technical notes
- Linked design brief when UI exists
- Approved ticket scope
- Acceptance criteria
- Dependencies
- Test notes
- Approval status
- Target repository

## Ready Checklist
- [ ] PRD reference exists.
- [ ] Architecture or technical notes exist.
- [ ] Design brief exists when UI is involved.
- [ ] Acceptance criteria are observable and testable.
- [ ] Dependencies are known.
- [ ] Data/API contracts are clear when relevant.
- [ ] Security/privacy implications are documented when relevant.
- [ ] UX/design requirements are clear when UI exists.
- [ ] Test notes are included.
- [ ] Target repository is identified.
- [ ] Approval is explicit.

## Not Ready Conditions
- Scope is broad or ambiguous.
- Acceptance criteria cannot be tested.
- Technical contract is missing.
- Approval is missing.
- Target repository is unclear.
- Critical dependency is unknown.

## Action When Not Ready
Do not start development. Route back to Product, Product Designer, Architect, QA Developer, or Security Reviewer based on the missing input.
