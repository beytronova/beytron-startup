# Definition of Done

Work is done only when implementation, validation, documentation, and handoff obligations are complete.

## Done Checklist
- [ ] Approved scope is implemented.
- [ ] Acceptance criteria are satisfied or exceptions are documented.
- [ ] Tests or validation notes exist.
- [ ] Test impact is documented.
- [ ] Security/privacy impact is documented when relevant.
- [ ] Release impact is documented.
- [ ] Known risks are recorded.
- [ ] Documentation is updated when behavior changes.
- [ ] Development-to-QA handoff is complete.
- [ ] QA status is explicit before release.

## Not Done Conditions
- Work exceeds ticket scope.
- Tests are skipped without explanation.
- Critical bug or blocker remains unresolved.
- Release impact is unknown.
- QA cannot determine what changed.

## Action When Not Done
Return to the responsible role with a blocker note using the relevant handoff file.
