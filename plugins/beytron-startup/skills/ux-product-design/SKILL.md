# UX Product Design

Use this skill when PRD scope needs product design planning before architecture, backlog, or implementation.

## Purpose

UX Product Design makes the intended user experience explicit enough for engineers, QA, and stakeholders to review.

## Required Inputs

- Approved or review-ready PRD.
- User personas and journeys.
- Brand/design constraints.
- Platform target: web, mobile, backend admin, or cross-platform.
- Accessibility and localization requirements.

## Outputs

- Design brief.
- User flow.
- Screen inventory.
- Component/state inventory.
- Interaction state matrix.
- Empty/loading/error/success states.
- Design handoff notes.

## Rules

- Do not skip accessibility and responsive behavior.
- Do not design features outside PRD scope without marking them as proposals.
- Do not imply implementation is approved.
- Include edge cases and failure states.

## Quality Bar

Design is ready for architecture/backlog only when flows, screens, states, content needs, and platform constraints are clear enough for estimation and QA planning.
