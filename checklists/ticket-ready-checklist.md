# Ticket Ready Checklist

Use this checklist before moving from backlog to development.

## Required Inputs
- Linked PRD or product scope
- Linked architecture or technical notes
- Design brief when UI exists
- Approved ticket scope
- Acceptance criteria
- Dependencies
- Test notes
- Approval status
- Target repository

## Checklist
- [ ] Ticket has clear summary and scope.
- [ ] Non-scope is explicit when needed.
- [ ] PRD or product scope is linked.
- [ ] Architecture or technical notes are linked.
- [ ] Design brief is linked when UI exists.
- [ ] Acceptance criteria are observable and testable.
- [ ] Dependencies are known.
- [ ] API/data contracts are clear when relevant.
- [ ] Security/privacy implications are documented when relevant.
- [ ] Test notes are included.
- [ ] Release impact is stated.
- [ ] Target repository is identified.
- [ ] Approval is explicit.

## Pass Criteria
Ticket can move to development when all required inputs are present and the implementing role can start without guessing product, technical, test, or repository context.

## Block Conditions
- Scope is broad or ambiguous.
- Acceptance criteria cannot be tested.
- Technical contract is missing.
- Approval is missing.
- Target repository is unclear.
- Critical dependency is unknown.

## Missing Information Output
```text
Ticket is not ready because:
Missing information:
Blocked role:
Owner to resolve:
Recommended next step:
```
