# Design Checklist

Use this checklist before moving from design to architecture, backlog, or development.

## Required Inputs
- PRD
- Target users
- User flows
- Platform constraints
- Screen inventory
- Interaction states
- Accessibility notes

## Checklist
- [ ] Primary user flows are defined.
- [ ] Secondary and failure flows are considered.
- [ ] Screen inventory is complete.
- [ ] Loading, empty, error, success, permission, and offline states are documented where relevant.
- [ ] Accessibility notes are included.
- [ ] Responsive or platform-specific behavior is documented.
- [ ] Design constraints and open questions are visible.
- [ ] Design does not introduce scope outside PRD.
- [ ] Analytics or event needs are flagged when relevant.
- [ ] Development handoff is understandable.

## Pass Criteria
Design can move forward when implementation and QA can understand screens, states, edge cases, and accessibility expectations without inventing UX decisions.

## Block Conditions
- Core flow is unclear.
- Critical screen or state is missing.
- Design contradicts PRD scope.
- Accessibility or platform constraints are unknown.

## Missing Information Output
```text
Design is blocked because:
Missing UX/state/platform information:
Affected role:
Recommended next step:
```
