# PRD Checklist

Use this checklist before moving from PRD to design, architecture, or backlog.

## Required Inputs
- Discovery summary
- Problem statement
- Target users
- MVP scope
- Acceptance criteria
- Metrics
- Risks
- Approval status

## Checklist
- [ ] Problem and target users are clear.
- [ ] Goals are explicit.
- [ ] Non-goals prevent scope creep.
- [ ] MVP scope is narrow and shippable.
- [ ] User flows include success and failure paths.
- [ ] Acceptance criteria are observable and testable.
- [ ] Metrics are measurable.
- [ ] Dependencies are listed.
- [ ] Risks are documented.
- [ ] Open questions are visible.
- [ ] Handoff notes exist for design, architecture, QA, and analytics when relevant.
- [ ] Approval status is stated.

## Pass Criteria
PRD can move forward when MVP scope, acceptance criteria, metrics, risks, and handoff notes are sufficient for design and architecture without guessing.

## Block Conditions
- MVP scope is broad or ambiguous.
- Acceptance criteria cannot be tested.
- Metrics cannot be measured.
- Target user is unclear.
- Product risk is material but undocumented.

## Missing Information Output
```text
PRD is blocked because:
Missing information:
Affected next workflow:
Owner to resolve:
Recommended next step:
```
