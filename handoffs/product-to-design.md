# Product to Design Handoff

## Purpose
Transfer product intent into UX and design work without losing scope, constraints, or testability.

## Source Role
Product

## Receiver Role
Product Designer

## Required Source Artifacts
- PRD
- Target users
- User problem
- MVP scope
- Non-goals
- Acceptance criteria
- Metrics
- Known constraints

## Handoff Checklist
- [ ] PRD link or artifact path is included.
- [ ] Primary user and problem are clear.
- [ ] MVP scope and non-goals are explicit.
- [ ] Acceptance criteria are testable.
- [ ] Required platforms are known.
- [ ] Open questions are listed.
- [ ] Approval state is included.

## Receiver Outputs
- Design brief
- User flows
- Screen inventory
- Interaction state matrix
- UX risks

## Acceptance Conditions
The handoff is accepted when the Product Designer can produce user flows and screen states without inventing product scope.

## Blocker Format
```text
Blocked because:
Needed from Product:
Impact if unresolved:
Recommended next step:
```

## Stop Conditions
- User flow is unclear.
- Acceptance criteria are not testable.
- Key constraints are missing.
- Approval state is missing.
