# Release to Growth

## Purpose
Turn a release into measurable growth, SEO, analytics, and learning loops.

## Trigger
A release is shipped or ready for launch planning.

## Required Approval
- Release approval for launch-sensitive work.
- Experiment approval when experiments affect users, pricing, messaging, or data collection.

## Required Roles
- Growth SEO
- Data Analytics
- Product
- Product Designer when messaging or landing UX changes
- Web Developer when web content changes are needed

## Required Inputs
- Release scope
- Product goals
- Target audience
- Existing analytics baseline
- Approved messaging constraints

## Steps
1. Read release scope and product goals.
2. Define launch messaging and SEO/content opportunities.
3. Define analytics events and success metrics.
4. Create experiment backlog.
5. Define learning review cadence and follow-up actions.

## Outputs
- Growth plan
- SEO/content plan
- Metrics plan
- Experiment backlog
- Follow-up learning loop

## Artifact Target
- Growth and metrics docs, or backlog items when approved.

## Tool Usage
- Web/search tools may be used for SEO and competitor research.
- Jira tools may be used for growth experiment tickets when requested.

## Failure Handling
- If target audience is unclear, return to Product.
- If metrics are unavailable, route to Data Analytics.
- If messaging would overpromise product capabilities, block launch messaging.
