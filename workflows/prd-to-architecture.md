# PRD to Architecture

## Purpose
Convert PRD and design context into technical architecture.

## Required Roles
- Architect
- Backend Developer when APIs/data are involved
- Mobile Lead or Web Developer depending on platform
- Security Reviewer for sensitive data

## Steps
1. Read PRD, design brief, and constraints.
2. Define modules, data flow, integrations, and contracts.
3. Identify risks and tradeoffs.
4. Produce development handoff.

## Outputs
- Architecture
- Data/API contracts
- Technical risks
- Development handoff

## Stop Conditions
- Core data model is unknown.
- Security or privacy impact is unclear.
- Platform constraints are unresolved.
