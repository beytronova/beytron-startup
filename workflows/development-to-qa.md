# Development to QA

## Purpose
Move implementation into validation with clear test scope and evidence.

## Required Roles
- QA Developer
- Automation Developer when repeatable checks are valuable
- Implementing developer

## Steps
1. Read implementation summary and ticket scope.
2. Build or update test plan.
3. Run available checks.
4. Record blockers, skipped tests, and release readiness.

## Outputs
- QA report
- Test cases
- Bug reports
- Release readiness recommendation

## Stop Conditions
- Implementation summary missing.
- Acceptance criteria missing.
- Critical blockers unresolved.
