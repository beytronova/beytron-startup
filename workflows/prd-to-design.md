# PRD to Design

## Purpose
Convert PRD scope into user flows, screen inventory, UX states, accessibility notes, and design handoff artifacts.

## Trigger
A PRD exists and UI, onboarding, workflow, or experience decisions are needed.

## Required Approval
- Minimum: `APPROVED_FOR_DESIGN`

## Required Roles
- Product Designer
- Product
- QA Developer for testable UX states
- Architect when design affects technical constraints

## Required Inputs
- PRD
- Acceptance criteria
- Target user notes
- Brand/platform constraints
- Approval status

## Steps
1. Read PRD and acceptance criteria.
2. Define primary, secondary, and failure flows.
3. Identify screens and interaction states.
4. Document accessibility, responsive, localization, and usability risks.
5. Produce design brief and handoff notes.

## Outputs
- Design brief
- User flows
- Screen inventory
- Interaction state matrix
- UX risks

## Artifact Target
- Design brief artifact in project docs or active idea workspace.

## Tool Usage
- Figma or design tools may be used only when requested or available.
- Do not create product code in this workflow.

## Failure Handling
- If PRD flow is unclear, return questions to Product.
- If accessibility or platform constraints are unknown, record blockers.
- If design affects architecture, route to Architect before backlog.
